# Tools: screenshots, shot comparison, the van audit, arms tools

The Godot tools these build on are `tooling.md`.

## Who runs what

- `tools/van_audit.py` (+ `tools/van_audit/`) boots the van at IDLE headless (seed 1337), collects every visible triangle in `VanRig` space and writes HEIGHT, REAR_ROOF, FLICKER, CLIP, OPENING, EDGE, LEAK_IN and LEAK_OUT findings with node paths to `.godot/van_audit/report.txt`; side doors and windows are posed closed, half and open without tweens, the gun port is skipped. It takes about 155 s alone; `--audit-passes=closed,half,open,win_half,win_open,tail` runs a subset, and `smoke.py` runs the seven as parallel strict shards and sums their `AUDIT SUMMARY` counts (`--plant-flicker` runs one unsharded audit). `smoke.py --shots` also saves the `c01`.. close-ups of doors, windows, side seams and the rear roof at IDLE.
- A full audit or smoke fails on `VAN AUDIT STALE EXEMPT: <key>` when an exempt rule in `van_audit_exempt.gd` exempted nothing, judged across all shards (`smoke.py` unions each shard's `AUDIT EXEMPT USED` line; keys carry no trailing space because the judge cuts one off the line's end). The leak rays use `RandomNumberGenerator` seed 1337.
- `tools/hand_shots.py` renders the first-person arms in one pose from the `arms cam` views (front, side, left, top, elbow) plus `player` (the player's own camera) into `<out>/<view>.png` in a single Godot launch: it builds `arms` console lines from a named pose (or takes raw ones) and runs `probe.py --shot <dir> --views ...`, whose runner switches `arms cam` per view (`player` is `arms cam off`), waits three frames and saves the viewport. Windows uses the hidden desktop; Linux cloud containers render it under `xvfb-run` (opengl3, Dummy audio).
- `arms touch` (`scripts/debug/debug_arms_touch.gd`) is a read-only check. Per hand it reports fingertips whose centre sits inside another finger's tube (`clip A tip vs B depth/p`) and the nearest gun part to each tip (`sd/p`, below 0 means the tip is inside it). For the right index tip it prints the gap to `Body/Trigger` against `TRIGGER_MAX_P` 0.25. The last line is `TOUCH OK` or `TOUCH CHECK n`. Smoke prints the last 3 lines and never fails on them. On main at 2026-10-03 it reads `TOUCH CHECK 20`: every clip is tip against neighbouring finger, and no tip is inside the gun.
- `tools/pose_sheet.py` makes one PNG grid per named pose of `hand_shots.py` (default views front, side, top, player; 2 columns of half-size cells with labels), one Godot launch per pose through `hand_shots.run_shots`, so a full sheet set takes about a minute per pose. Raw view PNGs go to `<out>/_views/` and are deleted unless `--keep`. Needs Pillow.
- `tools/shot_stats.py <shots_dir>` is pure Python (PIL): mean and p95 linear luminance, clipped share and saturation per `--shots` PNG, checked against the targets table in `.claude/rules/art-shots.md`.
- `tools/gap_check.py <shots_dir> [--strict]` is pure Python (PIL): it counts magenta pixels in the `g01`.. gap-light views that `smoke.py --shots` saves (`gap_views` in `smoke_shots_closeups.gd`, shot with `gaplight on` or `out`). It fails when the control view (the left side door open) is under 1 % magenta, and under `--strict` when any other view has a magenta pixel. The `g` views are judged by it, never by `shots.py compare`.

## Design choices

- **Screenshots need a window, on a desktop nobody sees.** Headless Godot renders nothing. On Windows `smoke.py --shots <dir>` runs the windowed smoke through `tools/hidden_desktop.run_hidden`, which starts Godot on its own Win32 desktop (`CreateDesktopW` + `STARTUPINFO.lpDesktop`, output through an inherited temp file, the desktop closed afterwards). The GPU renders there normally (checked on this machine, Forward+ on d3d12), and a window on another desktop can never show on, activate on or take focus from the owner's desktop. The old off-screen `--position` plus `no_focus` override still alt-tabbed the owner out of fullscreen games; never go back to it, and never fall back to a visible window if the desktop can't be created (the smoke fails instead). Every headless Godot launch also passes `CREATE_NO_WINDOW` so no console window flashes up. The game never sets `MOUSE_MODE_CAPTURED` while `SaveSandbox.enabled` (`fps_player._ready`, its click re-capture, `van._capture_mouse_after_ui_click`): capturing in the off-screen window clipped and hid the owner's real cursor and pulled them into it. Any new capture site needs the same guard. A minimized window stops drawing, so never minimize it. Cloud containers have no display. `tools/smoke/smoke_shots.gd` does the capturing: after a one-second settle (the rear doors take 0.9 s to open at a stop) it saves the player's view, the player turned 180° (the player only turns on mouse input, so the turn holds until undone), and a temporary Camera3D on `VanRig` 9 m up and 8 m ahead of the cab looking back (van-local -Z is the cab), hiding every CanvasLayer for the last two because the act reveal panel and the HUD cover the view. The van is an enclosed box: without the outside camera no shot shows the street. At IDLE `van_views` also saves exterior views of the van from rig-local cameras (side front, side rear, low front), plus the side front for each of N rerolled look seeds with `smoke.py --shots DIR --van-seeds N` (restored afterwards with `VanLook.rebuild`, never `reroll`). They number themselves `v01-`… so the main `01`..`12` numbering, which the art notes cite, never shifts; `shot_stats.py` calls them kind `van`.
- **Shots compare against measured noise.** `shots.py capture <name>` stores a full `smoke.py --shots` set in `.godot/shots/<name>/` (per checkout, gitignored, kept between sessions; reuse a `before` set instead of recapturing). `compare` matches PNGs by stem and scores each view as the mean absolute RGB difference on 0..255 (D30). The smoke is not frame-identical, so each view has its own tolerance in `TOLERANCE`: 2× the noise measured between two captures of one tree (2026-09-28), never below `TOLERANCE_FLOOR` 0.05 so views measured at 0 don't flag float jitter; a stem missing from the table (a new view, `--van-seeds` views) uses `DEFAULT_TOLERANCE` 1.0. The measured noise: `06-combat-outside` 4.74 (the raiders move, 2026-10-05), `04-combat-front` 0.30 (2026-10-05), `05-combat-back` 2.14 (2026-10-05), `02-idle-back` 0.31 (2026-10-05), `11-rear-park-stop-back` 0.49 (2026-10-05), every other view 0.16 or less, the exterior van views 0. The van drives at IDLE and the smoke waits on wall-clock timers, so `smoke_shots.gd` `pin_van()` stops the travel controller, puts the van at `_IDLE_SHOT_PROGRESS` (12 m) and zeroes and stops the wheel spin for the whole IDLE shot block, and `unpin_van()` restores it; without that every exterior view sat a few ticks further down the street each run (5 to 7 of noise, 45 views, 2026-10-01). `facade_lamp_flicker.gd` likewise holds its lamp steady on when `SaveSandbox.enabled`. `MachineMotion` (`scripts/van/look/machine_motion.gd`) stops its `_process` the same way (its spin moved the interior views and its flicker drew two global `randf()` per frame), and `shop_booth_flyers.gd` takes a fixed seed instead of `randomize()`. The gameplay rolls use the global stream, which a run consumes in frame order (gun spread, loot, wave timers), so `tools/smoke/smoke_seeds.gd` reseeds it right before each roll the smoke triggers itself: every `summon`, every `set_phase(REST)` (the 3-choice offer and the two `speed`-mode grants) and the shop stock (on `SceneTree.node_added`, because the stop is built inside `finish_turn`). A new roll the smoke triggers gets a pin there. What the real encounter spawns, hits and drops in the combat pass stays wall-clock dependent, so the combat views and the hull number on the stop HUDs keep measured noise (2026-10-05). Any new per-frame animator visible from outside the van (a `_process` on street or van dressing, a shader driven by `TIME`, anything that moves with the van's progress) must hold still the same way, or its views must be re-measured. So a change to combat-outside only shows when it is large; check it by eye. **Re-measure** after the smoke's shot choreography or a view list changes: capture two sets on one unchanged tree, run `compare <a> <b> --raw` (it prints the raw diffs and no verdict), double each value and write it into `TOLERANCE`, then confirm a third capture compares `SHOTS SAME`. `only-a`/`only-b` count as changed, so a renamed view fails until both sets have it.
